# Zapret Hub — каркас, менеджер zapret и тесты стратегий (подпроект 1)

Дата: 2026-10-10. Статус: согласована.

## 1. Цель

Одно приложение в трее вместо ручной работы с `service.bat`, `test zapret.ps1`, Wireshark и логами:
управлять Flowseal-zapret, подбирать стратегию по реальным тестам и показывать результат так,
чтобы лучшая стратегия была видна сразу и применялась в один клик.

Проект разбит на девять подпроектов, у каждого своя спецификация:

1. **Каркас + менеджер zapret + тесты** — этот документ.
2. **Диагностика** («почему не работает Discord/DbD/…») — отдельная спецификация.
3. **Маршрутизация через SOCKS5** (замена `discord-udp-proxy.ps1`) — отдельная спецификация.
4. **CLI для агентов:** команды с машиночитаемым выводом, чтобы ИИ-агент настраивал и тестировал
   всё без участия пользователя — отдельная спецификация.
5. **zapret2** (bol-van/zapret2: `winws2`, стратегии на Lua) рядом с Flowseal-zapret — отдельная
   спецификация.
6. **tg-ws-proxy** (Flowseal/tg-ws-proxy: локальный MTProto-прокси для Telegram через WebSocket):
   скачивание релиза, запуск вместе с хабом, состояние в трее, ссылка `tg://proxy` — отдельная
   спецификация. Добавлен 2026-10-17. Нужен только вместе с подпроектом 7 (решение 2026-10-17): под
   Windows Telegram и так работает через zapret и маршрутизацию.
7. **Linux:** перенос хаба на Linux (bol-van/zapret или zapret2 с `nfqws`/`nfqws2`, nftables, systemd,
   маршрутизация через TPROXY и cgroup, CLI через Unix-сокет) — отдельная спецификация. Добавлен
   2026-10-17.
8. **Стратегии Flowseal на zapret2:** все стратегии Flowseal (`general*.bat`) перенести на zapret2 (Lua,
   `winws2`) и положить в репозиторий, чтобы первый запуск хаба сразу имел их все, без ручного
   переноса. Проверить лицензию Flowseal перед включением в репозиторий. Добавлен 2026-10-17.
9. **Тест для circular:** удобный тест, который подбирает лучший набор приёмов для circular-стратегии
   zapret2 (по сервисам и по проходу). Добавлен 2026-10-17; заменяет прежнее решение «circular не
   делаем»: стратегию собирает тест, а не руками.

Очередь (2026-10-17): 1, 4, 5, 3 готовы; дальше 8 (стратегии Flowseal на zapret2), затем 2 (диагностика,
вместе с 9 — спецификация `2026-10-17-zapret-hub-diag-design.md`); 7 и 6 — в самом конце.

Подпроекты 2–5 здесь описаны только границами (разделы 4 и 13), чтобы каркас не пришлось переделывать.

## 2. Пользователи и окружение

- Автор и его друзья. Портативный exe, без установщика.
- Windows 10/11 x64.
- Любая папка Flowseal-zapret (`zapret-discord-youtube`, сейчас 1.10.3).
- Любой локальный SOCKS5-прокси (NekoBox, v2rayN, Clash и т.п.). Он нужен только для проверки
  доступности прокси на обзоре и для загрузок, если напрямую не вышло.
- Готовые профили сервисов: Discord, YouTube, Dead by Daylight/Steam. В подпроекте 1 они дают
  только дополнительные столбцы тестов (раздел 7.4).

## 3. Объём подпроекта 1

**Входит:**
- Tauri-приложение с треем, мастером первого запуска и автозапуском.
- Все функции `service.bat`: установка, удаление и статус службы, игровой фильтр, режим ipset,
  флаг автопроверки обновлений, замена активных фейков, обновление `ipset-all` и hosts, проверка
  версии, системные проверки из «Run Diagnostics», очистка кэша Discord.
- Свои стратегии: клонирование, редактирование, удаление.
- Тесты стратегий: стандартный и DPI 16–20, рейтинг, история, «применить лучшую».

**Не входит:**
- Диагностика по профилям и маршрутизация: подпроекты 2 и 3.
- CLI для агентов и zapret2: подпроекты 4 и 5.
- Автообновление самого приложения и автоматическая установка новой версии Flowseal: только
  уведомление и ссылка на релиз.
- Английский интерфейс: строки вынесены в один файл, перевод позже.

## 4. Архитектура

### 4.1. Репозиторий

`D:\zapret-hub`, Cargo workspace + Tauri v2 + Svelte 5 (стек как в cogit).

```
crates/
  exec/     запуск внешних программ: таймаут, отмена, журнал, вывод в OEM/UTF-16
  probe/    сетевые проверки (curl.exe, ICMP, SOCKS5)
  zapret/   модель папки Flowseal, служба, флаги, списки, обновления, системные проверки
  tester/   прогон стратегий, рейтинг, история
src-tauri/  IPC, трей, окно, автозапуск, настройки; тело команды ~10 строк, логика в крейтах
frontend/   Svelte 5
docs/       спецификации и планы
```

Зависимости: `probe → exec`; `zapret → exec, probe` (быстрая проверка после установки, загрузки
обновлений); `tester → exec, probe, zapret`; `src-tauri → все`. Крейты `diag` и `router` появятся
вместе со своими подпроектами: пустой крейт ничего не проверяет, а добавить крейт позже ничего не ломает.
Крейты не зависят от `tauri` (только `serde`/`specta`-derive для DTO).

### 4.2. Процесс

- Один процесс с правами администратора (манифест `requireAdministrator`). Права нужны для
  службы, `netsh`, hosts и WinDivert.
- Крестик окна прячет его в трей и выгружает WebView (`destroy`), ядро на Rust продолжает работать.
  Открытие из трея создаёт окно заново.
- «Выход» в меню трея завершает приложение. Служба zapret продолжает работать.
- Автозапуск — задача Планировщика «при входе пользователя, с наивысшими правами». При каждом
  запуске приложение сверяет путь к exe в задаче и обновляет его, если exe перенесли.

### 4.3. Хранение (портативно, рядом с exe)

```
zapret-hub.toml          настройки: путь к zapret, SOCKS5, автозапуск, тема, «запускать свёрнутым»,
                         router_enabled (маршрутизация, подпроект 3)
data/routes.toml         правила маршрутизации через SOCKS5 (подпроект 3)
data/strategies/*.toml   свои стратегии (источник истины)
data/tests/*.json        прогоны тестов
data/cache/dpi-suite.json  последняя загруженная копия набора hyperion-cs
data/state/pending.json  снимок состояния незавершённой операции (раздел 10)
data/logs/YYYY-MM-DD.log журнал операций
```

### 4.4. Совместимость с Flowseal

Приложение пишет флаги, списки и службу туда же и в том же формате, что `service.bat`.
Оригинальные `service.bat` и `test zapret.ps1` продолжают работать параллельно и видят изменения
приложения, и наоборот.

## 5. Модуль `zapret`

### 5.1. Поиск папки

По порядку:
1. `ImagePath` службы `zapret` в реестре (`...\bin\winws.exe` → корень папки).
2. Путь запущенного `winws.exe`.
3. Ручной выбор в мастере.

Папка считается правильной, если в ней есть `service.bat`, `bin\winws.exe`, `bin\WinDivert64.sys`
и `lists\`. Версия берётся из строки `set "LOCAL_VERSION=..."` в `service.bat`.

### 5.2. Список стратегий

- Все `*.bat` в корне, кроме `service*`, в естественном порядке (числа сравниваются как числа,
  как `Sort-Object` с `PadLeft(8)` в `service.bat`).
- Своя стратегия — файл `general (HUB <имя>).bat`, у которого есть запись в `data/strategies/`.
  Файл `HUB` без записи показывается как обычный.
- Активная стратегия — значение `zapret-discord-youtube` в
  `HKLM\System\CurrentControlSet\Services\zapret`.

### 5.3. Разбор `.bat` → аргументы winws

Точный порт разбора из `service.bat :service_install`:
- захват начинается со строки, содержащей `winws.exe`; в первой строке отрезается всё до
  `winws.exe"` включительно;
- токены `^` и `^^` пропускаются;
- подставляются переменные `%BIN%`, `%LISTS%`, `%GameFilter%`, `%GameFilterTCP%`,
  `%GameFilterUDP%`. Значения игрового фильтра вычисляются, как в `:game_switch_status`, а при его
  отключении подставляется порт `12`. Файл фильтра, который есть, но не читается, — ошибка разбора,
  а не «фильтр выключен»;
- аргумент в кавычках: если содержит `:`, остаётся как есть; если начинается с `@`, превращается в
  `@<папка>\остаток`; иначе в `<папка>\аргумент`. Результат снова берётся в кавычки;
- сохраняется машина состояний `mergeargs` (значения 0–3), включая склейку значений через `,` и `=`
  для `sni`, `host`, `altorder`;
- обработка `!` (`EXCL_MARK`).

Результат — список аргументов и строка «Final args», совпадающая с выводом `service.bat`
(проверяется эталонами, раздел 11).

### 5.4. Служба

- **Установка стратегии:** включить TCP timestamps (`netsh interface tcp set global timestamps=enabled`)
  → `net stop zapret` → `sc delete zapret` →
  `sc create zapret binPath= "\"<bin>\winws.exe\" <args>" DisplayName= "zapret" start= auto` →
  `sc description` → `sc start` → записать имя стратегии в реестр. Затем быстрая проверка: winws
  запущен через 2 с, и 2 цели из `targets.txt` дают `HTTP:OK`.
- **Удаление:** `zapret` (stop + delete), `taskkill winws.exe`, затем `WinDivert` и `WinDivert14`,
  как в `:service_remove`.
- **Статус:** состояния служб `zapret` и `WinDivert` (в том числе `STOP_PENDING` с подсказкой о
  конфликте), запущен ли `winws.exe`, есть ли `WinDivert64.sys`, имя активной стратегии.

### 5.5. Настройки Flowseal

- **Игровой фильтр:** файл `utils\game_filter.enabled` (`mode=all|tcp|udp`, `tcp=`, `udp=`), та же
  проверка диапазонов, что в `:validate_game_filter_range`. Отключение пишет `mode=disabled` и
  сохраняет диапазоны — так же, как `service.bat`. Аргументы зашиты в службу, поэтому после
  изменения активная стратегия переустанавливается (если служба установлена). Если в реестре нет
  имени стратегии, переустанавливать нечего: изменение откатывается с ошибкой «сначала примените
  стратегию».
- **Режим ipset:** `loaded`, `none` или `any` через `lists\ipset-all.txt` и `.backup`, переходы как
  в `:ipset_switch` (включая ошибку «нет бэкапа» при переходе в `loaded`). После смены служба
  перезапускается.
- **Автопроверка обновлений:** файл `utils\check_updates.enabled`.
- **Активные фейки:** `bin\ACTIVE_DISCORD_UDP.bin` и `bin\ACTIVE_GAME_UDP.bin`. Текущий фейк
  определяется по SHA-256 среди `bin\*.bin` (кроме `ACTIVE_*`). Замена — копия выбранного файла.
- **Свои списки:** `list-general-user.txt`, `list-exclude-user.txt`, `ipset-exclude-user.txt`.
  Если файла нет, он создаётся с тем же содержимым по умолчанию, что в `:load_user_lists`.
  Редактор: добавить или удалить строку, проверка формата домена и IP/CIDR.

### 5.6. Обновления

- **Версия Flowseal:** `.service/version.txt` из репозитория Flowseal (как в
  `:service_check_updates`). При запуске и раз в сутки, если включён флаг. Новая версия → значок на
  обзоре, уведомление, ссылка на релиз.
- **`ipset-all`:** загрузка `.service/ipset-service.txt` во временный файл, затем атомарная замена;
  старая копия сохраняется. Если напрямую не вышло, повтор через SOCKS5 (если он задан).
- **hosts:** загрузка `.service/hosts`, сравнение по первой и последней строке (как в
  `:hosts_update`). Если обновление нужно, показывается разница; по подтверждению содержимое
  вписывается в `%SystemRoot%\System32\drivers\etc\hosts` блоком между строками-маркерами
  `# zapret-hub begin` / `# zapret-hub end`, с бэкапом `hosts.zapret-hub.bak`. Повторное применение
  заменяет только свой блок.

### 5.7. Системные проверки

Те же, что в `:service_diagnostics`, со статусом «ок / внимание / проблема» и ссылками из
оригинала: BFE, системный прокси, TCP timestamps (с кнопкой «включить»), AdGuard, Killer, Intel
Connectivity Network Service, Check Point, SmartByte, кириллица в пути, OneDrive, наличие
`WinDivert64.sys`, службы VPN, безопасный DNS (`DohFlags`), записи YouTube в hosts, «WinDivert
работает без winws» (кнопка «удалить WinDivert»), конфликтующие службы `GoodbyeDPI`,
`discordfix_zapret`, `winws1`, `winws2` (кнопка «удалить», по подтверждению).

В подпроекте 1 они показываются на вкладке «Zapret»; в подпроекте 2 переезжают в «Диагностику».

### 5.8. Очистка кэша Discord

Для Stable, PTB, Canary и Development: закрыть процесс, удалить `Cache`, `Code Cache`, `GPUCache`
(как `:clear_discord_cache`). По подтверждению, с отчётом по каждой папке.

## 6. Свои стратегии

- **Создание:** «Клонировать» любую стратегию. Копия получает имя и запись в
  `data/strategies/<id>.toml`: имя, от какой стратегии клонирована, строка `--wf-*` и список блоков.
- **Модель:** первая строка — фильтр перехвата (`--wf-tcp`, `--wf-udp`), дальше блоки, разделённые
  `--new`. Блок хранится строкой аргументов с подстановками (`%BIN%`, `%LISTS%`, `%GameFilter…%`),
  как в `.bat`: её показывает и правит редактор, а разбирает тот же парсер (5.3).
- **Редактор:** блоки показаны карточками. В заголовке — фильтр блока (протокол, порты, `l7`,
  hostlist/ipset), в теле — аргументы текстом. Блоки можно добавлять, удалять, переставлять и
  дублировать.
- **Проверка перед сохранением:** аргументы разбираются тем же парсером (5.3) и проверяются запуском
  `winws.exe --dry-run`. Если эта версия winws не поддерживает `--dry-run`, winws запускается на 2 с
  и проверяется, что он не завершился с ошибкой (вывод показывается целиком).
- **Файл:** `general (HUB <имя>).bat` по тому же шаблону, что оригинальные стратегии (шапка с
  вызовами `service.bat`, `start "zapret: %~n0" /min "%BIN%winws.exe" ...` с переносами `^`).
  Поэтому стратегию видят `service.bat` и `test zapret.ps1`.
- **Восстановление:** при запуске приложение сверяет `data/strategies/` с папкой zapret и заново
  выкладывает недостающие файлы (например, после обновления Flowseal).
- **Удаление:** удаляются и запись, и файл. Активную стратегию удалить нельзя, пока не выбрана
  другая.

## 7. Тесты стратегий

### 7.1. Стандартный набор

- **Цели:** `utils\targets.txt` в формате Flowseal (`Ключ = "https://..."` или `"PING:ip"`).
  Если файла нет, используется встроенный список из `test zapret.ps1`.
- **Проверки для URL-цели:** три запуска `curl.exe` с теми же аргументами, что в скрипте:
  `-I -s -m 4 --connect-timeout 2 -o NUL --show-error` и `--http1.1` / `--tlsv1.2 --tls-max 1.2` /
  `--tlsv1.3 --tls-max 1.3`. К `-w` добавляется `%{time_total}` рядом с `%{http_code}`, сам запрос не
  меняется.
- **Статусы:** `OK` (код выхода 0); `SSL` (ошибки сертификата или «Could not resolve host», те же
  шаблоны, что в скрипте); `UNSUP` (код 35 или «not supported»); `ERROR` (всё остальное).
- **Ping:** ICMP, один запрос с таймаутом 1000 мс, как `System.Net.NetworkInformation.Ping` в скрипте.
- **Параллельность:** `min(16, max(8, ядра × 2))` целей одновременно; стратегии строго по очереди.

### 7.2. Набор DPI 16–20

- Набор hyperion-cs `tcp-16-20/suite.v2.json` (Apache-2.0, как в скрипте). Последняя удачно
  загруженная копия хранится в `data/cache/` и используется, если загрузка не удалась.
- Для каждой цели и каждого из HTTP/TLS1.2/TLS1.3: `curl.exe --range 0-65535 -m 5 --connect-timeout 3
  -X POST --data-binary @<64 КБ случайных байт> -w "%{http_code} %{size_upload} %{size_download}
  %{time_total}"`.
- Вердикт как в `Invoke-DpiSuite`: `LIKELY_BLOCKED`, если отправлено больше 0, принято 0, время ≥
  таймаута и код выхода не 0; иначе `OK`, `FAIL` или `UNSUPPORTED`.
- На время DPI-набора режим ipset переключается в `any` (как в скрипте) и затем восстанавливается.

### 7.3. Процедура прогона

До шага 1 DPI-набор загружается (или берётся из кэша) и пишется тело запроса: пока обход ещё
работает. Без набора прогон не начинается и ничего в системе не меняет.

1. Снимок состояния (раздел 10) и запись `data/state/pending.json`.
2. `sc stop zapret` и `zapret2` (вместо требования оригинального скрипта удалить службу) и
   завершение всех `winws.exe` и `winws2.exe` с ожиданием, пока процессы не исчезнут (их дескрипторы
   WinDivert закрыты). Командные строки запущенных вручную winws сохраняются в снимок. Если временные
   метки TCP выключены, они включаются, как при «Применить». Имена хостов целей разрешаются один раз
   заранее, чтобы DNS-запрос не попадал во время первой стратегии.
3. Для DPI-набора — переключение ipset в `any`.
4. «Повторов» N (1–5, по умолчанию 1) полных проходов по списку: сначала все стратегии, потом все
   ещё раз, а не N раз одна стратегия подряд — дрейф сети за минуты ложится на все стратегии. В каждом
   проходе для каждой выбранной стратегии:
   - убедиться, что ни один `winws.exe`/`winws2.exe` не работает (завершить с ожиданием);
   - запустить `bin\winws.exe` с аргументами из парсера (5.3), без окна, рабочая папка `bin`;
   - ждать до 5 с, пока процесс жив; если он завершился, сохранить его вывод и код как ошибку
     запуска стратегии и перейти к следующей;
   - пауза 300 мс, затем проверки набора;
   - завершить winws и дождаться его выхода.
5. Вернуть ipset, запустить службу (если она была запущена), запустить сохранённые вручную
   winws, удалить `pending.json`, если всё вернулось (раздел 10). Шаг 5 выполняется и после
   ошибки или паники в шагах 2–4.

При отмене во втором и дальше проходе недоделанный проход отбрасывается: у всех стратегий остаётся
одинаковое число проходов.

Стратегия запускается с теми же аргументами, что установил бы «Применить» (парсер `service.bat`).
Оригинальный скрипт запускает `.bat` через `cmd`; здесь сознательно тестируется ровно то, что
попадёт в службу.

«Отмена» прерывает текущую стратегию и сразу выполняет шаг 5; отмена до шага 1 (пока загружается
набор) завершает прогон, ничего в системе не меняя. Во время прогона кнопки, меняющие zapret,
заблокированы.

### 7.4. Рейтинг

Ключ сортировки стандартного набора, по возрастанию:
1. **Ошибки:** число проверок не `OK` (`ERROR`, `SSL` и `UNSUP`) из 3 × (число URL-целей) — сейчас
   36 (12 × 3). `UNSUP` считается: `curl.exe` из Windows (schannel) отдаёт сброс TLS-соединения,
   обычный ответ DPI, кодом 35, который скрипт помечает как `UNSUP`.
2. **Задержка:** медиана `time_total` успешных проверок.
3. Порядок меню `service.bat`.

ICMP-пинг winws не обрабатывает (он перехватывает только TCP и UDP), поэтому пинг одинаков для всех
стратегий и сортировать по нему бессмысленно. Он показывается отдельным столбцом, а «по пингу» в
смысле «быстрее» реализовано через задержку HTTPS, которая от стратегии зависит.

DPI-набор: сначала меньше `LIKELY_BLOCKED`, потом меньше `FAIL`.

Стратегии, которые не запустились (7.3, шаг 4), идут после всех остальных; между собой, как и при
равенстве ключей, — по порядку меню. Это относится к обоим наборам.

С повторами (7.3, шаг 4) рейтинг строится по сводке проходов: счётчики (проверки, ошибки, `FAIL`,
`LIKELY_BLOCKED`, пинг, профили) складываются — у всех стратегий одинаковое число проходов, поэтому
порядок тот же, что по средним; задержки — медиана медиан проходов; ошибка запуска в любом проходе —
ошибка стратегии. Каждый проход сохраняется в `passes` результата; в таблице под медианой задержки
показан разброс медиан проходов (мин.–макс.), в подсказке к ошибкам — ошибки каждого прохода.

Дополнительные столбцы профилей (только информация, в сортировку по умолчанию не входят):
- Discord: успешность HTTPS к `discord.com`, `gateway.discord.gg`, `cdn.discordapp.com`,
  `updates.discord.com`;
- YouTube: `www.youtube.com`, `i.ytimg.com`, `redirector.googlevideo.com`;
- DbD/Steam: время TLS к `steam.live.bhvrdbd.com`, `api.epicgames.dev`, `store.steampowered.com`.

Цели профилей, которых нет в `targets.txt`, проверяются отдельно и в 36 не считаются.

Таблицу можно отсортировать по любому столбцу. Кнопка «Применить лучшую» ставит первую строку
рейтинга (5.4).

### 7.5. Результаты

`data/tests/<YYYY-MM-DD_HH-MM-SS>.json`: набор, версия Flowseal, список стратегий с
SHA-256 их аргументов, по каждой стратегии и цели — статусы, коды, времена, вывод ошибок запуска.
История показывает прогоны списком. Результат стратегии в списке стратегий — последний прогон, в
котором она участвовала (если с тех пор аргументы изменились, результат помечается «устарел»).
Кнопка «Копировать» выдаёт текст в формате `test zapret.ps1`.

## 9. Интерфейс

### 9.1. Вкладки

- **Обзор:** карточки «Служба» (состояние, стратегия), «Flowseal» (версия, обновление),
  «Прокси» (SOCKS5 отвечает, задержка), «Последний тест» (лучшая стратегия, ошибки, когда).
  Кнопки «Применить лучшую», «Запустить тесты», «Перезапустить zapret».
- **Стратегии:** таблица с поиском; справа подробности — аргументы по блокам и результаты.
  Кнопки «Применить», «Клонировать»; для своих также «Изменить» и «Удалить».
- **Тесты:** выбор набора и стратегий, живой прогресс (стратегия N из M, заполняющаяся таблица),
  результаты с сортировкой, история, «Применить лучшую», «Копировать».
- **Zapret:** игровой фильтр, ipset, автопроверка обновлений, фейки, обновления ipset и hosts,
  свои списки, системные проверки, очистка кэша Discord, удаление службы.
- **Настройки:** папка zapret, адрес SOCKS5, автозапуск, «запускать свёрнутым», тема.
- «Маршруты» и «Диагностика» появляются в подпроектах 3 и 2.

Тема светлая/тёмная по системной. Интерфейс на русском, все строки в одном файле.

### 9.2. Мастер первого запуска

1. Папка zapret: найденные варианты (5.1) или выбор вручную, с проверкой.
2. SOCKS5: можно пропустить. Предлагаются найденные кандидаты: порт из конфига NekoBox
   (`inbound_socks_port`), если NekoBox найден, и порты по умолчанию известных клиентов (NekoBox 2080,
   v2rayN 10808, Clash 7890). Показываются только те, что сейчас слушают на `127.0.0.1` и
   отвечают на рукопожатие SOCKS5.
3. Автозапуск: да/нет.

### 9.3. Трей

- Иконка: зелёная — служба работает и последняя быстрая проверка (5.4) прошла; жёлтая — служба
  работает, но проверка не прошла; серая — служба остановлена или не установлена.
- Меню: «Открыть»; «Стратегия: <имя>» с подменю «Переключить на» (топ-5 рейтинга);
  «Перезапустить zapret»; «Быстрая проверка»; «Выход».
- Быстрая проверка каждые 30 минут и по кнопке.
- Уведомления Windows: тесты завершены (лучшая стратегия и её ошибки); быстрая проверка перестала
  проходить; вышла новая версия Flowseal.

## 10. Ошибки и сохранность состояния

- Каждое системное действие (`sc`, `net`, `netsh`, `reg`, `taskkill`, запуск winws, `curl.exe`,
  загрузки, запись файлов) записывается в журнал: команда, код выхода, полный stdout и stderr.
  Ничего не обрезается.
- Ошибки уходят в одну очередь уведомлений: ошибки первыми, ничего не теряется, закрытие показывает
  следующее.
- **Снимок состояния** перед любой изменяющей операцией (смена стратегии, тесты, ipset, игровой
  фильтр, удаление службы): есть ли служба, её `binPath`, тип запуска, состояние, имя стратегии в
  реестре, командные строки запущенных `winws.exe`, режим ipset, наличие бэкапа ipset, игровой фильтр
  (`utils\game_filter.enabled`). Записывается в `data/state/pending.json` до первого изменения и
  удаляется после успеха; если откат не удался, файл остаётся. Новая изменяющая операция при
  оставшемся `pending.json` сначала восстанавливает его; не вышло — операция не начинается.
  Не начинается она и тогда, когда снимок не читается целиком: служба есть, а её `binPath` из
  реестра не читается, или список ipset либо файл игрового фильтра есть, но не читается (откат по
  такому снимку вернул бы другое состояние). Отсутствующий файл — это `any` и выключенный фильтр,
  как в `service.bat`.
- При ошибке операция откатывается к снимку. Если при запуске приложения найден `pending.json`,
  приложение сообщает о прерванной операции и восстанавливает снимок.
- Изменяющие операции идут через одну очередь, строго по одной. Чтение статуса параллельно.
- У каждого внешнего процесса таймаут; зависший процесс завершается, это записывается как ошибка.
- Исключение — долгоживущий winws: тестовый (его запускает, останавливает и читает `procs::Winws`)
  и ручной winws, возвращаемый из снимка. Таймаута у них нет по смыслу; командная строка и pid
  пишутся в журнал при запуске.

## 11. Тестирование

- **Эталоны парсера.** Скрипт `tools/gen-bat-fixtures.cmd` прогоняет код разбора из
  `service.bat :service_install` (без `sc create`) по каждому `general*.bat` и сохраняет «Final args»
  в `crates/zapret/tests/fixtures/`. Тест на Rust сравнивает свой результат побайтно. Набор
  обновляется вместе с версией Flowseal.
- **Модульные тесты:** естественная сортировка, рейтинг (7.4), разбор `targets.txt`, классификация
  вывода `curl.exe` (на сохранённых примерах), генерация `.bat` своих стратегий (сгенерировал →
  разобрал → те же аргументы), флаги, ipset-переходы и hosts-блок на временных папках.
- Тесты, которым нужны права администратора, служба или WinDivert, помечены `#[ignore]` и
  запускаются вручную.
- **Фронтенд:** `svelte-check`, vitest для сортировки таблиц и хранилищ.
- **Ручной чек-лист перед выпуском:** установка и удаление службы; смена стратегии; полный прогон
  стандартного набора; отмена посередине; принудительное завершение приложения посреди прогона и
  восстановление при следующем запуске; DPI-набор с возвратом ipset.

  спецификация. В подпроекте 1 CLI нет.
- **zapret2 (подпроект 5):** второй движок рядом с Flowseal: своя папка, `winws2`, стратегии на

  Поправка (спецификация zapret2, 3.1): общего интерфейса движка нет, трейт не выделяется.

  - Крейт `zapret` знает второй движок только по именам `zapret2` и `winws2.exe` (единый снимок,
    исключительность служб, быстрая и системные проверки); остальное — в крейте `zapret2`.

Детальный дизайн каждого — в его собственной спецификации.

## 14. Риски и открытые вопросы

- **`winws --dry-run`.** Проверено: `winws.exe` из Flowseal 1.10.3 знает `--dry-run` (строка есть в
  его справке). Запасной путь (6) остаётся для сборок без него.
- **Изменения формата Flowseal.** Новые конструкции в `.bat` сломают паритет парсера; эталоны (11)
  это поймают.
- **Время прогона.** Примерно 15 с на стратегию, все 22 стратегии Flowseal 1.10.3 — около 6 минут.
  Это ожидаемо и показывается заранее.
- **Антивирусы.** Приложение запускает `winws.exe` и правит службы и hosts; в подпроекте 1 оно не
  содержит своего WinDivert. Ложные срабатывания на сам exe возможны, README объяснит.

Решено при согласовании: в таблице оба столбца — ICMP-пинг и задержка HTTPS; второй ключ рейтинга —
задержка HTTPS (7.4).

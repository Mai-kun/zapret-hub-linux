# Zapret Hub — CLI для агентов (подпроект 4)

Дата: 2026-10-11. Статус: решения приняты без пользователя по его поручению («сделай подряд, без
остановок или вопросов»); каждое записано в разделе 12 с ценой ошибки.

Основа: спецификация подпроекта 1 (`2026-10-10-zapret-hub-core-design.md`, далее «core»), её
раздел 13 задаёт границы.

## 1. Цель

ИИ-агент (Claude Code и т.п.) без участия пользователя смотрит состояние, применяет стратегии,
меняет списки и флаги, запускает тесты и читает рейтинг. Вывод машиночитаемый (JSON), коды выхода
постоянные.

## 2. Объём

**Входит:**
- `zapret-hub-cli.exe` рядом с `zapret-hub.exe`, в том же zip.
- Все действия окна, кроме чисто оконных (раздел 6).
- Ожидание прогона тестов и компактный рейтинг.
- Запуск приложения через задачу автозапуска.
- Настройка «Управление из командной строки», по умолчанию выключена.

**Не входит:**
- Человекочитаемые таблицы: вывод только JSON (кроме текста `tests report`).
- Управление по сети: канал только локальный.
- zapret2: подпроект 5 добавит свои команды в этот же протокол.

## 3. Архитектура

```
crates/cli/            без tauri
  src/lib.rs           протокол: Request (enum), Response, версия, кадрирование
  src/pipe.rs          именованный канал: сервер с ACL, клиент
  src/main.rs          бинарь zapret-hub-cli: clap → Request → канал → stdout
src-tauri/src/cli.rs   сервер в приложении: поток приёма, проверка настройки, диспетчер
```

Зависимости: `cli → zapret, tester` (типы аргументов и итогов); `src-tauri → cli`.

CLI — отдельный пакет. Манифест `requireAdministrator` из `tauri-build` встраивается во все
бинарники пакета `src-tauri`, а CLI должен запускаться без прав.

## 4. Как CLI достаёт до повышенного процесса

Работающее приложение (оно уже с правами администратора) слушает именованный канал
`\\.\pipe\zapret-hub-cli`. CLI без прав подключается, отправляет одну команду, получает ответ.
Сам CLI ничего в системе не меняет, кроме запуска задачи «Zapret Hub» командой `start` (ниже).
Все изменения идут через очередь и снимок приложения (core 10): zapret по-прежнему меняет один процесс.

Если приложение не запущено, `zapret-hub-cli start` запускает задачу Планировщика «Zapret Hub»
(`schtasks /Run /TN "Zapret Hub"`). Задача создана приложением с наивысшими правами, поэтому
приложение стартует повышенным без UAC. Если задачи нет (автозапуск выключен), `start` объясняет,
что приложение нужно запустить вручную или включить автозапуск. После запуска `start` ждёт канал
до 30 с.

## 5. Безопасность канала

- Настройка `cli_enabled`, по умолчанию `false`. Флажок в «Настройках»: «Управление из командной
  строки (zapret-hub-cli)». Пояснение под ним: «Любая программа, запущенная от вашего имени, сможет
  менять zapret через приложение».
  - Пока флажок выключен, канал на любую команду отвечает ошибкой
    `the CLI is off: enable it in Zapret Hub → Settings` (код 3).
  - Переключение действует сразу, без перезапуска.
- DACL канала:
  - SYSTEM и Администраторы — полный доступ;
  - пользователь, от которого запущено приложение (SID из токена процесса), — чтение и запись;
  - остальным доступа нет.
- Метка целостности Medium (`S:(ML;;NWNR;;;ME)`): программы из песочниц (Low) не могут ни писать
  в канал, ни читать из него.
- `PIPE_REJECT_REMOTE_CLIENTS`: подключения по сети отклоняются.
- `FILE_FLAG_FIRST_PIPE_INSTANCE` у первого экземпляра. Если имя уже занято чужим процессом,
  приложение канал не открывает, пишет это в журнал и показывает уведомление «Канал CLI занят
  другой программой».
- Канал выполняет только фиксированный список команд (раздел 6). Путей клиента сервер не открывает.
- Папку zapret через канал не сменить: служба запускает `winws.exe` этой папки от SYSTEM.
  Сохранение настроек из канала, в котором `zapret_dir` отличается от текущей, приложение
  отклоняет: `the zapret folder can be changed only in the Zapret Hub window (Settings)`. Папку
  меняет только окно (решение 13).
- Запрос длиннее 1 МиБ отклоняется.
- Каждая команда попадает в журнал приложения: `cli: <cmd>` и итог (`ok` или ошибка целиком).

Остаточный риск. Включённый CLI даёт программам, запущенным от имени пользователя, те же действия,
что окно: удаление службы, правку hosts, свои стратегии. Аргументы своей стратегии получает
`winws.exe` службы, а она работает от SYSTEM, поэтому параметры winws, которые пишут файлы, пишут
их от SYSTEM. Это не больше, чем может любой, кто пишет в папку Flowseal: он меняет сами `.bat` и
`winws.exe`. Направить службу на другой `winws.exe` через канал нельзя: папку zapret меняет только
окно.

## 6. Протокол

Один запрос — одно подключение. Клиент пишет строку JSON с `\n`. Сервер отвечает строкой JSON
с `\n` и закрывает канал.

- Запрос: `{"v":2,"cmd":"apply_strategy","args":{"name":"general (ALT11)"}}`.
  - `cmd` и `args` совпадают с именами и аргументами IPC-команд окна (`bindings.ts`).
  - Новая команда одна: `tests_status`.
- Ответ: `{"ok":true,"data":…}` или `{"ok":false,"error":"…"}`. Текст ошибки — с цепочкой причин,
  не усекается.
- `{"ok":false,"refused":true,"error":"…"}` — приложение команду не выполняло: CLI выключен,
  запрос больше 1 МиБ, не разбирается или содержит неизвестную команду, чужая версия протокола.
  CLI выходит с кодом 3, а не 1: агенту нужно чинить окружение, а не команду.
- `v` — версия протокола, сейчас 2 (поправка: с 0.5.0 версия 2, до этого 1). На другую версию сервер отвечает отказом
  `protocol v<N> is not supported: update zapret-hub-cli.exe and Zapret Hub together`.

В коде запрос — enum с `#[serde(tag = "cmd", content = "args", rename_all = "snake_case")]`.
Клиент строит его типизированно, сервер разбирает исчерпывающим `match`, и компилятор не даст
забыть команду. Добавить команду — добавить вариант; `v` растёт только при несовместимом изменении.

Не входят:
- `pick_folder`, `open_url`, `open_folder` — оконные;
- `check_folder` — открыл бы путь клиента, а папку zapret через канал не сменить (раздел 5);
- `take_notices` — забрал бы уведомления у окна;
- `test_live` — его заменяет `tests_status`.

`--yes` повторяет подтверждения окна (core 5.6–5.8). Без него команда не отправляется, код 2.

Уточнения:
- `version` работает и без приложения: `{"cli": "0.2.0", "protocol": 2, "app": "0.2.0" | null}`,
  код 0.
- `start`: если канал отвечает и CLI включён — `{"app": "<версия>"}` сразу. Если канал отвечает, а CLI
  выключен, — код 3 с текстом отказа, задача не запускается. Если канала нет — запуск задачи и
  ожидание; код 3, если задачи нет или канал не ответил за 30 с.
- `proxy check` без адреса берёт `socks5` из настроек; если его нет — код 2.
- `game-filter`: не указанные `--tcp`/`--udp` берутся из текущего состояния (`get_flowseal`).

Значения перечислений в CLI пишутся в kebab-case, в протоколе — как в `bindings.ts`:
- списки: `general`, `exclude`, `ipset-exclude`;
- исправления: `enable-tcp-timestamps`, `remove-windivert`, `remove-conflicts`;
- игровой фильтр: `disabled`, `all`, `tcp`, `udp`;
- фейки: `discord`, `game`.

## 7. CLI

- stdout — один JSON-документ с отступами. При успехе — `data`, при ошибке —
  `{"error": "…"}`. Исключение: `tests report` печатает текст отчёта.
- Коды выхода:

  | Код | Значение |
  |---|---|
  | 0 | успех |
  | 1 | приложение выполнило команду с ошибкой (`ok:false`), или прогон тестов завершился ошибкой |
  | 2 | ошибка в аргументах или нет `--yes` |
  | 3 | приложение недоступно или отказало (`refused`): не запущено, CLI выключен, канал занят дольше 10 с, версия протокола не совпала |
  | 4 | `tests wait` или `--wait` упёрлись в `--timeout` |

- `--help` у каждой команды (clap).
- Долгие команды (применение, исправления, обновления) ждут ответа сколько нужно. Если агент
  прервёт CLI, приложение доведёт операцию до конца (очередь); повторный `status` покажет итог.

### 7.1. Тесты

- `tests run` без имён запускает все стратегии из `strategies list` в их порядке, но без строк
  с `error`. С `--dpi` — набор DPI.
  - Без `--wait` команда возвращается сразу:
    `{"started": true, "suite": "standard", "strategies": N}`.
  - С `--wait` дальше ведёт себя как `tests wait`.
- `tests wait` опрашивает `tests_status` раз в 2 с до конца прогона.
  - Ход пишется в stderr строками вида `3/33 general (ALT2)`.
  - `--timeout <s>` ограничивает ожидание; по умолчанию без ограничения.
  - Итог — компактный рейтинг или ошибка прогона (код 1).
  - Если прогона нет и нечего ждать, печатается последний итог (`last`).
- `tests_status` возвращает `{testing, live, last}`.
  - `live` — как `test_live`.
  - `last` — итог последнего завершённого прогона с запуска приложения: `{run_id}` или `{error}`.
  - Приложение хранит `last` в памяти: новое поле `AppState`, его ставит `jobs::finish`.
- Компактный рейтинг (`tests show <id>` и итог ожидания):
  `{id, suite, canceled, restore_error, ranking: [{place, name, score, launch_error}]}`.
  - `--full` печатает весь `TestRun`.
  - Порядок — как в прогоне: он уже ранжирован (core 7.4).

Агент с ограничением времени на команду (у Claude Code — 10 мин) повторяет
`tests wait --timeout 540`, пока не получит код 0 или 1.

### 7.2. Настройки

`settings set <key> <value>`: CLI читает настройки, меняет один ключ и отправляет все.

- Ключи как в `zapret-hub.toml`: `socks5`, `autostart`, `start_minimized`, `theme`, `cli_enabled`.
- `zapret_dir` среди них нет: папку zapret меняет только окно (раздел 5). `settings get` её
  показывает, `settings set zapret_dir` — неизвестный ключ.
- Пустое значение для `socks5` значит «нет».
- Булевы значения — `true` или `false`; тема — `system`, `light` или `dark`.
- Неизвестный ключ — код 2 со списком известных.
- `cli_enabled false` выключает CLI. Включить его из CLI нельзя: выключенный канал не выполняет
  команд.

### 7.3. Свои стратегии

- `custom validate` и `custom save` читают JSON формы `CustomStrategy` (`name`, `cloned_from`, `wf`,
  `blocks`) из файла или из stdin (`-`).
- Исходник для правки: `custom clone`, затем `strategies show "general (HUB <имя>)"` → поле `record`.

## 8. Изменения в приложении

- `Settings.cli_enabled: bool`, по умолчанию `false`; флажок в «Настройках» с пояснением (раздел 5).
- `src-tauri/src/cli.rs`:
  - поток сервера стартует в `setup`, на каждого клиента — свой поток;
  - диспетчер вызывает те же `commands::*`, асинхронные — через `tauri::async_runtime::block_on`;
  - поэтому очередь, снимки, `changed()` и тексты ошибок у CLI и окна общие: окно и трей сразу
    видят изменения, сделанные агентом.
- `AppState` хранит итог последнего прогона (7.1) — для команды `tests_status`.
- Журнал: строка на каждую команду (раздел 5).

## 9. Тестирование

- `cli`, протокол:
  - JSON каждого варианта `Request`: `cmd` и `args` совпадают с IPC (проверка на образцах);
  - разбор ответа;
  - предел 1 МиБ;
  - отказ на чужую версию.
- `cli`, канал: интеграционный тест в одном процессе, без прав:
  - сервер на уникальном имени, эхо-обработчик, клиент;
  - второй сервер на том же имени не стартует (`FIRST_PIPE_INSTANCE`);
  - SDDL содержит SID текущего пользователя.
- `cli`, бинарь:
  - разбор аргументов clap → `Request` по таблице раздела 6;
  - `--yes` и коды выхода;
  - слияние настроек;
  - компактный рейтинг.
- Приложение:
  - отказы (выключен, размер, разбор, версия) — чистая функция от строки запроса и флага,
    тестируется без Tauri;
  - `tests_status` собирается из состояния.
- Проверка вживую (приложение с правами + CLI) — вручную, по `docs/cli.md`.

## 11. Риски

- Клиент, который подключился и молчит, держит один поток сервера. Остальных клиентов это не
  задерживает. Локальная программа пользователя может навредить и проще — защиты нет.
  `ponytail`: асинхронный канал с таймаутом, если это когда-нибудь понадобится.
- Имя канала одно на машину. Второй пользователь с запущенным Zapret Hub получит «канал занят».
  Служба zapret тоже одна на машину, поэтому два приложения конфликтуют и без CLI.
- `schtasks /Run` без прав работает только для задачи, которую приложение создало с правами
  (автозапуск). Без неё `start` объясняет, что делать.

## 12. Решения

Каждое решение записано в формате «что — почему — цена ошибки».

1. **Канал к работающему приложению, а не повышенный запуск CLI.** UAC требует человека, агент
   его не нажмёт. Цена ошибки: если окажется нужным CLI без приложения, придётся добавить режим
   с повышенным запуском; протокол и команды останутся.
2. **CLI выключен по умолчанию.** Это новый вход в повышенный процесс; пользователь включает его
   один раз в «Настройках». Цена ошибки: один щелчок при первой настройке.
3. **Проверка `cli_enabled` на каждый запрос; канал открыт всегда.** Переключение без перезапуска
   потока. Цена ошибки: при выключенном CLI канал существует и отвечает отказом — атакующий узнаёт
   только то, что приложение запущено.
4. **JSON-строка в обе стороны, один запрос на подключение, `v` в запросе.** Это проще всего
   отлаживать, а новые команды обратно совместимы. Цена ошибки: за потоковым ходом прогона
   приходится опрашивать, а не подписываться.
5. **Запрос — tagged enum с именами IPC-команд.** Исчерпывающий `match`, одна таблица имён для окна
   и CLI. Цена ошибки: переименование IPC-команды меняет протокол; ловится тестом на образцах.
6. **Отдельный пакет `crates/cli` (lib + bin), clap.** В пакете `src-tauri` бинарник получил бы
   манифест администратора; ~38 команд вручную не разбирать. Цена ошибки: одна новая зависимость
   (clap).
7. **Диспетчер вызывает `commands::*` через `block_on`.** Одна реализация на окно и CLI. Цена
   ошибки: если команда начнёт требовать окно (`AppHandle` с WebView), CLI получит ошибку этой
   команды, а не падение.
8. **`--yes` на действия, которые в окне подтверждаются.** Агент не удалит службу случайно. Цена
   ошибки: лишний флаг в рецептах.
9. **Итог прогона хранится в памяти (`tests_status.last`), не на диске.** Если прогон упал до
   записи истории, его ошибку агент иначе не узнает. Перезапуск приложения итог теряет, но прогон
   тогда тоже прерван. Цена ошибки: после перезапуска `tests wait` вернёт `last: null`.
10. **Вывод только JSON, кроме `tests report`.** CLI для агентов; отчёт в формате
    `test zapret.ps1` — текст для людей и форумов. Цена ошибки: человеку читать JSON.
11. **`start` через задачу автозапуска.** Это единственный путь к повышенному запуску без UAC,
    и он уже создан пользователем. Цена ошибки: без автозапуска агент приложение не поднимет.
12. **Имя канала фиксированное, одно на машину.** Служба zapret тоже одна. Цена ошибки: на
    компьютере с двумя одновременно вошедшими пользователями CLI работает только у первого.

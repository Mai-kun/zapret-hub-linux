# Zapret Hub — zapret2 как второй движок (подпроект 5)

Дата: 2026-10-11. Статус: решения приняты без пользователя по его поручению («сделай подряд, без
остановок или вопросов»). Каждое решение записано в разделе 13 с ценой ошибки.

Основа:
- спецификация подпроекта 1 (`2026-10-10-zapret-hub-core-design.md`, далее «core»), её раздел 13
  задаёт границы;
- спецификация CLI (`2026-10-11-zapret-hub-cli-design.md`, далее «cli»).

Исследование zapret2 (bol-van/zapret2, master `a1adf7b`, релиз v1.0.5.2) — в заметках к
подпроекту; здесь только выводы.

## 1. Цель

Пробовать стратегии zapret2 (`winws2.exe`, стратегии на Lua) рядом со стратегиями Flowseal:
- тестировать их тем же тестером и в том же рейтинге;
- ставить лучшую службой в один клик;
- переключаться между движками без ручной работы;
- делать всё это из окна и через CLI.

## 2. Объём

**Входит:**
- Папка zapret2 в «Настройках»: проверка, версия движка, совместимость Lua.
- Стратегии zapret2:
  - встроенные — только чтение;
  - свои — текстовые файлы `<папка zapret2>/strategies/<имя>.txt` (переносятся из `data/zapret2` при первом запуске).
  - Простой редактор: текст аргументов, «Проверить», «Сохранить», «Удалить»; встроенную можно
    клонировать.
- Служба `zapret2`, переключение движков, снимок обоих движков.
- Тесты: в одном прогоне можно смешивать стратегии обоих движков.
- Системные проверки и быстрая проверка с учётом второго движка.
- Команды CLI для своих стратегий zapret2. Остальные команды работают с именами `zapret2:…` без
  изменений.

**Не входит:**
- Загрузка и обновление движка: пользователь скачивает релиз сам. «Настройки» дают ссылку на
  релизы; уведомлений о новых версиях нет.
- Конвертер стратегий Flowseal → zapret2: он теряет смысл (autottl, altorder), а сторонние
  конвертеры не проверены на живом трафике Windows.
- Свои списки и фейки zapret2: стратегии берут их из папки Flowseal (раздел 5). Без папки Flowseal
  работают только стратегии без её подстановок (5.1).
- blockcheck2 и подбор стратегий по одной технике.

## 3. Архитектура

```
crates/zapret2/   папка движка, версия и совместимость, стратегии, подстановки, проверка,
                  установка службы
crates/zapret/    знает второй движок только по именам: служба `zapret2`, процесс `winws2.exe`
                  (исключительность, снимок, быстрая проверка, системные проверки)
crates/tester/    при прогоне выбирает движок по имени стратегии
src-tauri/        настройка, команды, обзор
crates/cli/       новые варианты Request и подкоманды
```

Зависимости:
- `zapret2 → zapret, exec`;
- `tester → zapret2`;
- `src-tauri → zapret2`;
- `cli` новых зависимостей не получает: аргументы новых команд — строки и флаги, ответ печатается
  как есть.

### 3.1. Поправка к core 13

Core 13 обещал выделить общий интерфейс движка, когда появится второй движок. Решение: трейта нет.
Вместо него:
- **Пространство имён.** Стратегия zapret2 везде называется `zapret2:<имя>`. Имя стратегии
  Flowseal — имя `.bat`-файла, а в именах файлов Windows двоеточия не бывает, так что пересечений
  нет. `Request.strategies`, история, рейтинг, трей и CLI работают со строками, как раньше.
- **Пара `(служба, процесс)`.**
  - `zapret::service::active()` возвращает `("zapret2", "winws2.exe")`, если служба `zapret2`
    установлена.
  - Иначе — `("zapret", "winws.exe")`.
- **Ветвление по префиксу** в трёх местах:
  - запуск стратегии в тестере;
  - карточка стратегии;
  - применение стратегии.

Трейт выделяется при третьем движке или если таких мест станет больше пяти: три ветки покажут,
каким он должен быть.

## 4. Папка движка

- Корень — папка, где лежит `lua\zapret-lib.lua`. Сначала проверяется выбранная папка, затем
  `<выбранная>\zapret-winws` (так устроен zapret-win-bundle).
- `winws2.exe` ищется по порядку: в корне, в `bin\`, в `binaries\windows-x86_64\` (полный zip
  релиза).
- Рядом с `winws2.exe` должны быть `cygwin1.dll`, `WinDivert.dll`, `WinDivert64.sys`.
- В `lua\` должны быть `zapret-lib.lua` и `zapret-antidpi.lua`.
- Ошибка проверки называет каждый недостающий файл.
- Путь с кириллицей отклоняется: Cygwin его не переносит (та же проверка, что core 5.7).
- Папка zapret2 в корне диска отклоняется.
- Версия и совместимость:
  - `winws2.exe --version` печатает строку
    `github version <тег> (<коммит>) lua_compat_ver <N>`;
  - первая строка `lua\zapret-lib.lua` задаёт `NFQWS2_COMPAT_VER_REQUIRED`;
  - если числа не совпадают, это ошибка «движок и Lua из разных релизов».
- Версия читается при выборе папки и при первом запросе обзора или настроек (не при запуске приложения), затем кэшируется по времени изменения
  `winws2.exe`. Неудачный запуск `winws2.exe` (антивирус, занятый файл) не кэшируется и повторяется при
  следующем запросе. `--version` требует прав (манифест), а приложение их имеет.
- Новая настройка `zapret2_dir`. Пока она пуста, строк zapret2 нигде нет и движок ни на что не
  влияет.

## 5. Стратегии zapret2

### 5.1. Формат

Текст аргументов `winws2` после глобальной части:
- `--wf-*`;
- `--lua-init`, `--blob`;
- профили через `--new`.

Правила:
- переносы строк допустимы;
- строка, которая начинается с `#`, — комментарий. `#` внутри строки — синтаксис zapret2 (`#var`),
  его не трогаем.

Подстановки, путь всегда с `\` на конце:

| Подстановка | Значение |
|---|---|
| `%LUA%` | `<корень zapret2>\lua\` |
| `%FILES%` | `<корень zapret2>\files\` (фейки zapret2; есть в полном zip релиза) |
| `%LISTS%` | `lists\` папки Flowseal: те же списки, свои списки и режим ipset, что у Flowseal |
| `%BIN%` | `bin\` папки Flowseal: фейки `.bin`, включая активные |
| `%GameFilter%`, `%GameFilterTCP%`, `%GameFilterUDP%` | как у Flowseal (core 5.5): игровой фильтр общий |

Командная строка = `--chdir="<корень>" ` + развёрнутый текст.
- `--chdir` нужен, потому что у службы рабочая папка — `System32`.
- Тест, проверка и служба используют одну и ту же строку, поэтому её SHA-256 — ключ свежести
  результата (core 7.5).
- Папка Flowseal для zapret2 необязательна (решение 4). Без неё:
  - подстановки `%LISTS%`, `%BIN%` и `%GameFilter*%` — ошибка статической проверки с именем
    подстановки: «the strategy uses %LISTS%: choose the zapret folder in Settings»;
  - встроенные стратегии (5.2) используют списки и фейки Flowseal, поэтому в списке они с этой
    ошибкой, а прогон и «Применить» их отклоняют; работают свои стратегии на `%LUA%` и `%FILES%`;
  - очередь изменений (core 10) работает без папки: `change_any` отдаёт папку Flowseal, если она
    задана, и отказывает, только когда не задана ни одна из двух папок. Операции только Flowseal
    (его стратегии, игровой фильтр, ipset, фейки, списки, hosts, обновления, системные проверки)
    по-прежнему требуют папку и отвечают «the zapret folder is not set: choose it in Settings»;
  - снимок записывает службы и процессы обоих движков, а файлы Flowseal (ipset, игровой фильтр) —
    только при заданной папке. Откат снимка с файлами без папки — ошибка шага «files», службы
    откатываются всё равно, `pending.json` остаётся;
  - быстрая проверка берёт встроенный список целей `test zapret.ps1` вместо `targets.txt`;
  - прогон тестов из одних стратегий zapret2 идёт без папки; стратегия Flowseal в нём без папки —
    отказ до любых изменений. DPI-набор без папки не включает режим ipset `any` (его нет).

### 5.2. Встроенные и свои

- Встроенные стратегии (1–3) зашиты в приложение и только читаются.
  - Источник — пример из документации zapret2 (`docs/readme.md`, лицензия MIT, указана в
    комментарии), переведённый на списки и фейки Flowseal.
  - Без папки Flowseal они не работают (5.1). Вариант на `files\` zapret2 не сделан: в релизе
    zapret2 нет списков доменов, а стратегия без списков меняла бы весь трафик 80/443 — это не тот
    же профиль. Кому нужен zapret2 без Flowseal, пишет свою стратегию из шаблона.
  - Живьём они не проверены. Проверку на трафике пользователь делает тестом.
- Свои стратегии — `<папка zapret2>/strategies/<имя>.txt` (переносятся из `data/zapret2` при первом запуске).
  - Имя проходит ту же проверку, что имена своих стратегий Flowseal (core 6): 1–40 символов,
    буквы, цифры, пробел и `-_.`, начинается с буквы или цифры; имена устройств Windows (`CON`, `NUL`, `COM1`…) отклоняются.
  - Своя стратегия с именем встроенной — ошибка.
- Порядок в списках: сначала встроенные, затем свои в естественном порядке, всё после стратегий
  Flowseal.
- Сохранение — `save_zapret2(name, text, create)`, по правилам `save_custom` (core 6):
  - `create` и имя уже есть — ошибка;
  - не `create` и имени нет — ошибка;
  - перед записью — полная проверка (5.3);
  - если сохраняется активная стратегия, служба ставится заново с новой строкой, под снимком.
- Удаление активной стратегии запрещено, как у своих стратегий Flowseal.
- «Клонировать» встроенную — тот же `save_zapret2(новое имя, текст, create)`: редактор заполняется
  её текстом.
- Карточка стратегии (`get_strategy`) несёт исходный текст в новом поле `source`; у стратегий
  Flowseal оно пустое.

### 5.3. Проверка

По порядку, до первой ошибки:
1. **Статическая.**
   - Каждая функция из `--lua-desync=<функция>` должна быть определена как `function <функция>(`
     в одном из мест:
     - `lua\*.lua`;
     - встроенный код `--lua-init=<код>`;
     - файлы `--lua-init=@<файл>`.
   - В развёрнутой строке не должно быть `\"`: подстановка перед кавычкой дала бы экранированную
     кавычку.
2. **`--dry-run`.**
   - Команда: `winws2.exe <строка> --wf-dup-check=0 --dry-run`. Флаги стоят в конце: `--dry-run`
     перед неизвестным ключом молча завершает процесс с кодом 1.
   - Успех — код 0 и строка `command line parameters verified`.
3. **`--intercept=0`.**
   - Команда: `winws2.exe <строка> --intercept=0`.
   - Настоящая инициализация Lua: проверяет совместимость и наличие функций.
   - Загружает драйвер WinDivert с пустым фильтром, трафик не трогает.
   - Код 87 — ошибка Lua; вывод показывается целиком.

Проверку запускают «Проверить», «Сохранить» и каждое применение.

Статическая проверка входит и в список стратегий: строка с её ошибкой показывается с `error`, как
битый `.bat` (core 5.2). Её нельзя применить, и CLI `tests run` без имён её пропускает (cli 7.1).

### 5.4. circular

`circular` из `luazapret-auto.lua` — оркестратор внутри профиля: инстансы после него с
`strategy=K` образуют вариант K (номера с 1 без пропусков), выполняется только текущий вариант
хоста; после `fails` неудач (по умолчанию 3) хост переходит к следующему, вариант с `final` —
последний. Неудачи считаются по входящим пакетам, поэтому перед circular нужен `--in-range`.

- **Разбор** (`zapret2::circular::analyze`): по профилям — фильтр, аргументы circular
  (`fails`, `retrans`, остальные как есть), варианты (инстанс = вызов без `strategy=`/`final` и
  действующий `--payload`), инстансы без меток. Карточка стратегии (`StrategyDetail.circular`) и
  конструктор читают одно и то же.
- **Проверка** входит в статическую (5.3). Ошибки: номера `strategy=` не 1, 2, 3… подряд или не
  число; `strategy=` до circular или без него (все варианты шли бы сразу); circular без вариантов;
  два circular в профиле. Предупреждения (карточка, конструктор): нет `--in-range` (не `x`) перед
  circular; инстансы без `strategy=` после circular не выполняются никогда.
- **Запись** (`apply`): десинк-часть профиля (`--payload`, `--in-range`, `--out-range`,
  `--lua-desync`) заменяется на `--out-range=-s34228`, `--in-range=-s5556 --lua-desync=circular…`,
  `--in-range=x` и варианты с `strategy=K` (`final` у первого инстанса последнего, если задан);
  `--payload=` пишется там, где меняется. Новый профиль встаёт после выбранного. Остальные строки
  не трогаются, концы строк сохраняются. Недостающие `--blob=tls_google`/`stun2` (готовые варианты
  конструктора) добавляются после последней глобальной строки. Текст — источник истины: конструктор
  после записи читает его снова.
- **Объединение** (`merge`, 2–5 стратегий): основа — текст первой. Профиль первой ищется в каждой
  другой по фильтру (те же опции в любом порядке). Становится circular, только если он есть во всех,
  нигде не circular, везде с инстансами, наборы инстансов различаются и это TCP без UDP; вариант —
  каждый различный набор в порядке выбора, `fails`/`retrans` по умолчанию. Иначе профиль берётся из
  первой, а предпросмотр называет причину; профили других стратегий без пары не входят, блоб с тем же
  именем и другим значением остаётся из первой. Недостающие `--blob`/`--lua-init` других
  добавляются в начало. Результат открывается в редакторе как новая стратегия: сохранение — обычное,
  с проверкой.
- Команды `zapret2_profiles`, `zapret2_circular`, `zapret2_merge` — только окно: CLI пишет текст
  стратегии сам.

## 6. Служба и переключение движков

- Служба `zapret2`, отображаемое имя `zapret2`, автозапуск.
  - Имя выбрано не случайно: `winws1`/`winws2` у сторонних сборок уже отмечаются как конфликтующие
    службы (core 5.7).
  - `ImagePath` = `"<путь>\winws2.exe" <строка>`.
- Имя стратегии хранится в значении `zapret-discord-youtube` на ключе службы `zapret2`, как у
  Flowseal, с полным именем `zapret2:<имя>`. Поэтому `zapret::service::strategy()` отдаёт имя
  активной стратегии любого движка без перевода.
- Установлен один движок. Применение стратегии zapret2 (`change_safely("apply")`, снимок до первого
  шага):
  1. проверка (5.3); до неё ничего не меняется;
  2. остановить и удалить службу `zapret`, завершить `winws.exe`;
  3. остановить и удалить прежнюю `zapret2`;
  4. включить временные метки TCP (как Flowseal);
  5. создать и запустить `zapret2`, записать имя стратегии;
  6. через 2 с — быстрая проверка (core 5.4).
- Применение стратегии Flowseal удаляет `zapret2` и завершает `winws2.exe`. Это делает сама
  установка службы Flowseal, поэтому правило работает во всех путях: применение, переустановка
  при смене игрового фильтра, сохранение активной своей стратегии, трей.
- Драйвер WinDivert при переключении не удаляется: он общий, его держит и ручной winws.
  «Удалить службу» удаляет службу любого движка и драйверы, как сейчас.
- Смена игрового фильтра переустанавливает активную службу любого движка: порты зашиты в её
  аргументы. Смена режима ipset и фейка перезапускает активную службу.
- Снимок (core 10) хранит обе службы, оба значения стратегии и ручные процессы обоих движков.
  - Откат: файлы → остановить обе службы и оба процесса → вернуть службы → запустить ручные
    процессы.
  - Старый `pending.json` без новых полей читается: поля по умолчанию пустые.
  - `pending.json`, записанный до zapret2 (без метки `zapret2`), откатывает только Flowseal и не трогает
    службу zapret2 и winws2.

## 7. Тесты

- Прогон может смешивать стратегии обоих движков. Для каждой стратегии запускается её движок.
- Перед прогоном останавливаются обе службы и оба процесса; после прогона снимок возвращает
  движок, который был активен.
- Готовность `winws2`:
  - строка `windivert initialized. capture is started.`; как и у winws, если её нет 5 с, процесс
    считается готовым (первая загрузка драйвера бывает медленной);
  - затем ещё 2 с;
  - процесс должен быть жив, иначе это ошибка запуска с полным выводом (код 87 — ошибка Lua).
- `LUA ERROR` в выводе после проверок — ошибка запуска: такая стратегия ничего не делает, и без
  этого правила рейтинг поставил бы её выше честных.
- В прогоне сохраняется `zapret2_version`, если в нём были стратегии zapret2.
- Рейтинг, история и отчёт не меняются: имена с префиксом сортируются так же.
- Стратегия zapret2 при пустой или битой папке движка: прогон отказывается начинаться, пока
  ничего не изменено.

## 8. Окно

- **Мастер первого запуска:** на первом шаге рядом папка Flowseal (найденные кандидаты, выбор, «Без
  zapret») и папка zapret2 (поле, выбор, итог проверки `check_zapret2_folder`). Дальше можно, когда
  хотя бы одна папка рабочая и ни одна выбранная не с ошибкой. Только zapret2 — предупреждение о
  встроенных стратегиях (5.1).
- **Без папки Flowseal:** на «Обзоре» нет карточки Flowseal и ошибки папки; на вкладке zapret вместо
  настроек Flowseal — «Папка zapret не выбрана» (служба и кэш Discord остаются), системных проверок
  нет; в «Новой стратегии» и в «Тестах» нет Flowseal.
- **«Настройки»:**
  - поле «Папка zapret2» с выбором папки;
  - итог проверки: версия, совместимость Lua или ошибка;
  - ссылка на релизы `https://github.com/bol-van/zapret2/releases`.
- **«Обзор»:** в карточке «Служба» — какой движок активен; строка версии zapret2 или её ошибка.
- **«Стратегии»:**
  - строки `zapret2:<имя>` с меткой «zapret2»;
  - карточка показывает глобальную часть и профили (по `--new`) и итоговую командную строку;
  - встроенные: «Клонировать» (имя для копии);
  - свои: редактор текста, «Проверить», «Сохранить», «Удалить» (с подтверждением);
  - у zapret2 нет «Клонировать» в редактор Flowseal: форматы разные.
- **«Тесты»:** выбор стратегий включает строки zapret2.
- **Трей:** ничего нового — список лучших уже состоит из имён.

## 9. Системные проверки

- «WinDivert без winws» не срабатывает, пока работает `winws2.exe`: иначе приложение предложило бы
  удалить драйвер, которым пользуется zapret2.
- Если установлены и `zapret`, и `zapret2`, это конфликт: службу `zapret` мог поставить
  `service.bat` Flowseal, который о zapret2 не знает. «Удалить конфликтующие» удаляет `zapret2`,
  а приоритет отдаётся последнему действию пользователя вне приложения. Следующее «Применить»
  наводит порядок.

## 10. CLI

Новые команды:

| CLI | `cmd` | Нужен `--yes` |
|---|---|---|
| `zapret2 info` | `zapret2_info` (папка, версия, совместимость, ошибка) | |
| `zapret2 validate <file\|->` | `validate_zapret2` | |
| `zapret2 save <name> <file\|-> [--create]` | `save_zapret2` | |
| `zapret2 delete <name>` | `delete_zapret2` | да |

- `apply`, `strategies show`, `tests run` принимают имена `zapret2:…` без изменений.
- Папка zapret2, как и папка Flowseal, меняется только в окне: она решает, какой `winws2.exe` служба
  запустит от SYSTEM, поэтому канал CLI её не меняет (cli 5, решение о `zapret_dir`). `settings get`
  показывает `zapret2_dir`, `settings set` её не принимает.
- Версия протокола не меняется (cli 6): новые варианты добавляются.

## 11. Тестирование

Без прав администратора:
- открытие папки на разных раскладках и названия недостающих файлов;
- разбор баннера `--version` и `NFQWS2_COMPAT_VER_REQUIRED`;
- комментарии, подстановки, `--chdir`, разбиение на профили;
- статическая проверка, `\"`;
- командные строки `--dry-run`, `--intercept=0` и `ImagePath`;
- снимок со старым `pending.json`;
- вердикт готовности (живой процесс, `LUA ERROR`) как чистая функция;
- строки каталога и смешанный рейтинг;
- каждая встроенная стратегия проходит статическую проверку по сохранённому списку функций
  `zapret-lib`/`zapret-antidpi`/`zapret-auto`.

С правами (`#[ignore]`, вручную):
- проверка встроенных настоящим `winws2.exe`;
- применение в обе стороны;
- смешанный прогон;
- откат после убийства приложения посреди применения.

Нужен скачанный релиз zapret2. Агенты его не скачивают и не запускают — это делает пользователь.

## 12. Риски

- **zapret2 молод.**
  - Совместимость Lua менялась трижды за 8 месяцев.
  - Опции переименовывались.
  - Свежесть результата по SHA-256 строки не видит обновления движка, поэтому версия движка
    хранится в прогоне.
  - `ponytail`: добавить версию в хэш, если старые результаты начнут вводить в заблуждение.
- **Встроенные стратегии не проверены на живом трафике.** Тест покажет; рейтинг поставит
  неработающие вниз.
- **`service.bat` и `test zapret.ps1` Flowseal не знают о zapret2.** Скрипт может поставить
  `zapret` рядом с `zapret2` или оставить `winws2.exe` во время своего теста. Системная проверка
  (раздел 9) это показывает.
- **Сторонние сборки на базе zapret2.** У них свои службы (`winws2`, `zapret`) и задачи
  автозапуска. `winws2` уже считается конфликтом; задачи Планировщика сторонних GUI приложение
  не ищет.
- **Пути с пробелами внутри `--lua-init=@…` в аргументах службы.** Кавычки проходят через разбор
  Cygwin. Встроенные стратегии берут пути из подстановок в кавычках; проверка `\"` ловит
  поломанный случай.

## 13. Решения

Каждое решение записано в формате «что — почему — цена ошибки».

1. **Префикс `zapret2:` вместо трейта движка (поправка к core 13).** Различаются три места; всё
   остальное — общий код с двумя строками. Цена ошибки: при третьем движке понадобится выделить
   трейт по этим трём веткам.
2. **`zapret` знает второй движок только по именам `zapret2`/`winws2.exe`.** Нужен один
   `pending.json` с одним порядком отката, а `zapret` не может зависеть от `zapret2`. Цена ошибки:
   крейт Flowseal содержит две строки про чужой движок.
3. **Служба называется `zapret2`, а не `winws2`.** `winws2` у сторонних сборок — конфликт (core
   5.7). Цена ошибки: инструкции из интернета про `sc query winws2` к приложению не подходят.
4. **Списки, фейки и игровой фильтр берутся из папки Flowseal, но сама папка для zapret2
   необязательна.** Форматы совпадают, свои списки и ipset работают сразу для обоих движков. Без
   папки Flowseal работает zapret2 один: его стратегии, служба, тесты; подстановки Flowseal дают
   ошибку проверки (5.1). Цена ошибки: встроенные стратегии без Flowseal не запускаются, и тот, у кого
   только zapret2, начинает со своей стратегии.
5. **Движок не скачивается приложением.** Так же, как Flowseal (core 3): исполняемые файлы ставит
   пользователь. Цена ошибки: один ручной шаг.
6. **Встроенных стратегий 1–3, из примера документации zapret2.** Конвертеры сторонних авторов
   теряют смысл и не проверены на живом трафике. Цена ошибки: если они не работают у провайдера
   пользователя, нужны свои (редактор и CLI это позволяют).
7. **Проверка = статическая + `--dry-run` + `--intercept=0`.** `--dry-run` не видит Lua, а строка
   готовности печатается до инициализации Lua. Цена ошибки: проверка грузит драйвер WinDivert на
   долю секунды.
8. **`--chdir="<корень>"` в начале каждой командной строки.** У службы рабочая папка `System32`.
   Цена ошибки: нет.
9. **Только строки-комментарии `#`.** `#var` — синтаксис zapret2. Цена ошибки: комментарий в конце
   строки ломает стратегию, и проверка это покажет.
10. **`LUA ERROR` после проверок — ошибка запуска.** Ошибки Lua во время работы не фатальны, и
    стратегия, которая ничего не делает, иначе обогнала бы честные. Цена ошибки: стратегия с
    редкой безобидной ошибкой уходит вниз рейтинга.
11. **Переключение движка не удаляет драйвер WinDivert.** Драйвер общий, его может держать ручной
    winws. Цена ошибки: если версии драйвера у движков разойдутся, понадобится «Удалить службу» и
    повторное применение.
12. **Простой текстовый редактор вместо полей.** Формат zapret2 — список вызовов Lua с параметрами;
    поля для него — отдельный проект. Цена ошибки: пользователь правит аргументы как текст.
13. **Никаких уведомлений о новых версиях zapret2.** YAGNI: ссылка на релизы в «Настройках».
    Цена ошибки: пользователь узнаёт об обновлении сам.

# zapret-hub-cli

`zapret-hub-cli.exe` — командная строка для работающего Zapret Hub. Она сделана для ИИ-агентов (Claude Code
и другие) и скриптов: каждая команда печатает один JSON-документ, коды выхода постоянные.

## Как это устроено

CLI прав администратора не просит и сам в системе делает только одно: `start` запускает задачу автозапуска
приложения (раздел «Если приложение не запущено»). Остальные команды он передаёт работающему приложению через
локальный канал `\\.\pipe\zapret-hub-cli`. Приложение уже запущено с правами и выполняет
команду тем же кодом, что кнопки окна: через ту же очередь операций, со снимком для отката. Поэтому окно и трей
сразу показывают, что сделал агент, а тексты ошибок у CLI и окна одни и те же.

Каждая команда попадает в журнал приложения `data\logs\ГГГГ-ММ-ДД.log`: `cli: apply_strategy: ok` или
`cli: apply_strategy: <текст ошибки>`. Команды, которые приложение не выполняло, — строкой
`cli: refused: <причина>`. Ожидание прогона (`tests wait`, `tests run --wait`) спрашивает приложение раз в 2 с,
и каждый вопрос — строка `cli: tests_status: ok`.

Если агент прервёт CLI посреди долгой команды (применение стратегии, исправление, загрузка), приложение
доведёт её до конца. Итог покажет следующий `zapret-hub-cli status`.

## Как включить

По умолчанию CLI выключен. Включите его один раз: «Настройки» → «Командная строка» → флажок «Управление из
командной строки (zapret-hub-cli)» → «Сохранить». Переключение действует сразу, без перезапуска.

Пока флажок выключен, приложение отвечает на любую команду отказом
`the CLI is off: enable it in Zapret Hub → Settings` (код 3). Выключить CLI можно и из него самого
(`settings set cli_enabled false`), включить — только в окне.

Канал принимает команды от пользователя Windows, который запустил Zapret Hub, а также от SYSTEM и
администраторов. Программы других пользователей и подключения по сети в канал не пускаются; программы из
песочниц (низкий уровень целостности) не могут ни писать в канал, ни читать из него.

Включённый CLI даёт любой программе, запущенной от вашего имени, те же действия, что окно: удаление службы,
правку `hosts`, свои стратегии. Аргументы своей стратегии получает `winws.exe`, а служба zapret запускает его от
SYSTEM, поэтому параметры winws, которые пишут файлы, пишут их от SYSTEM. Это не больше, чем может любая
программа, которая пишет в папку Flowseal: она меняет сами `.bat` и `winws.exe`.
Со zapret2 это прямее: текст своей стратегии содержит `--lua-init`, то есть Lua-код. Любая программа от вашего
имени с включённым CLI может выполнить произвольный Lua-код от администратора одним `zapret2 validate` (проверка
запускает `winws2` с `--intercept=0`, а `--lua-init` грузит Lua из текста) и от SYSTEM через `zapret2 save` и
`apply` (служба zapret2). Лишнего риска нет, только если папка zapret2 и так доступна этой программе на запись
(обычно так, когда папка в вашем профиле): тогда она меняет сам `winws2.exe` и его Lua. Иначе включайте CLI, только
если доверяете каждой запускаемой программе. Папки
zapret и zapret2, а с ними и то, какие `winws.exe` и `winws2.exe` запускают службы, CLI не меняет: их меняют
только в окне.

## Вывод и коды выхода

stdout — один JSON-документ с отступами, в UTF-8. При успехе это данные команды, при ошибке —
`{"error": "…"}` с полным текстом ошибки. Исключение — `tests report`: он печатает текст отчёта.
Команда, которой нечего вернуть (`custom validate`, `custom save`, `zapret2 validate`, `zapret2 save`,
`tests cancel`, `ipset update` и т. п.), печатает `{"ok": true}`. Единственное `null` со
смыслом — `flowseal check-update`: обновления нет. Ход (`tests wait`, `tests run --wait`) идёт в stderr,
в stdout — только итоговый JSON.
Порядок ключей в объектах не значим.

| Код | Значение |
|---|---|
| 0 | успех |
| 1 | приложение выполнило команду с ошибкой, или прогон тестов завершился ошибкой |
| 2 | ошибка в аргументах или нет `--yes`: CLI отклонил команду сам, ничего не изменено |
| 3 | приложение недоступно или отказало, команда не выполнялась: не запущено, CLI выключен, канал занят дольше 10 с, версии CLI и приложения не совпадают. Исключение: ``Zapret Hub closed the connection without a full answer, so the command may have run: check with `zapret-hub-cli status` `` — команда могла выполниться |
| 4 | `tests wait` или `tests run --wait` упёрлись в `--timeout` |

Код 0 значит, что команда выполнена, а не что проверка прошла: `apply`, `apply-best`, `restart`, `quick-check`
(и `custom save` активной стратегии) печатают итог быстрой проверки, `proxy check` — итог проверки прокси, и
код у них 0 при любом итоге. Читайте поле `ok`: `"ok": false` — проверка не прошла.

Код 3 значит «чинить окружение, а не команду»: запустить приложение, включить CLI, обновить `zapret-hub.exe`
и `zapret-hub-cli.exe` вместе. Исключение — канал, закрытый без полного ответа: команда могла выполниться,
поэтому сначала `zapret-hub-cli status`, а не повтор вслепую.

Код 2 значит, что ничего не изменено, но не всегда, что в приложение ничего не ушло: `proxy check` без адреса
сначала читает настройки и только потом отказывает, если `socks5` не задан. Сам CLI проверяет только форму
команды: аргументы, значения из списков, `true`/`false`, `--yes`, JSON своей стратегии. Остальное — адрес в
`settings set socks5`, имена стратегий, порты, записи списков — проверяет приложение, и его отказ — код 1.

`zapret-hub-cli --help` и `zapret-hub-cli <команда> --help` перечисляют команды и аргументы.

PowerShell читает вывод программ в кодировке `[Console]::OutputEncoding`. Чтобы кириллица в JSON не
испортилась, выполните перед вызовами `[Console]::OutputEncoding = [Text.Encoding]::UTF8`.

Значения перечислений пишутся через дефис (`ipset-exclude`, `remove-windivert`), ключи настроек — как в
`zapret-hub.toml` (`start_minimized`). Имя стратегии — имя её файла без `.bat`, например `"general (ALT11)"`;
стратегии zapret2 называются `zapret2:<имя>`, например `zapret2:general` (раздел «Стратегии zapret2»).

- `pick_folder`, `open_url`, `open_folder` — открывают окна, файловый менеджер и браузер;
- `check_folder`, `check_zapret2_folder` — открыли бы путь, переданный клиентом (второй ещё и запустил бы из него

- `test_live` — его заменяет `tests status`;
- `validate_route`, `import_route_lines` — проверка и импорт строк в редакторе правила окна.

## Настройки

`settings set <key> <value>` читает все настройки, меняет одну и сохраняет их, как кнопка «Сохранить» в окне:
приложение проверяет адрес прокси, включает или выключает автозапуск. Окно сразу показывает
новые значения: открытая вкладка «Настройки» следует за ними, пока вы в ней ничего не правили. Если правка
уже есть, вкладка оставляет вашу копию, и «Сохранить» запишет её поверх изменений агента.

| Ключ | Значение |
|---|---|
| `socks5` | `адрес:порт`, например `127.0.0.1:2080`; `""` — без прокси (в Windows PowerShell 5.1 — `'""'`, см. ниже) |
| `autostart` | `true` или `false` |
| `start_minimized` | `true` или `false`: при автозапуске оставаться в трее |
| `theme` | `system`, `light` или `dark` |
| `cli_enabled` | `false` выключает CLI; включить его из CLI нельзя |

Папки zapret и zapret2 (`zapret_dir`, `zapret2_dir`) CLI не меняет: службы zapret и zapret2 запускают из них
`winws.exe` и `winws2.exe` от SYSTEM, поэтому папки меняют только в окне («Настройки» → «Папка zapret» или
«Папка zapret2» → «Сохранить»). `settings get` их показывает, а `settings set zapret_dir …` и
`settings set zapret2_dir …` — неизвестный ключ, код 2. По той же причине скачать релиз Flowseal или zapret2
(«Скачать последний релиз…») можно только в окне: у CLI такой команды нет.

Сохранение через CLI не может включить `cli_enabled`: если вы выключили его в окне, пока команда читала и
сохраняла настройки, он остаётся выключенным. Если за это время вы сменили в окне папку zapret или zapret2,
приложение отклонит сохранение CLI ошибкой
`the zapret folder can be changed only in the Zapret Hub window (Settings)` или
`the zapret2 folder can be changed only in the Zapret Hub window (Settings)` (код 1): повторите команду.

Неизвестный ключ, не `true`/`false` у флажка или тема не из списка — код 2 со списком допустимых, до обращения
к приложению. Адрес `socks5` проверяет приложение: неверный — код 1 с его ошибкой
(`… is not an address like 127.0.0.1:2080`), настройки не меняются.

```
zapret-hub-cli settings set socks5 127.0.0.1:2080
zapret-hub-cli settings set socks5 ""
```

Windows PowerShell 5.1 не передаёт программам пустой аргумент: `""` пропадает, и CLI отвечает кодом 2, будто
значения нет. В нём пишите `'""'`:

```
zapret-hub-cli settings set socks5 '""'
```

## Маршруты

Правила маршрутизации через SOCKS5 (`data\routes.toml`). `routes add` и `routes edit` берут файл с таблицей
`[rule]` без `name`: имя — аргумент команды. `-` — stdin.

```toml
[rule]
enabled = true
protocol = "udp"                  # "tcp" | "udp" | "both"
ports = ["19294-19344", "50000-65535"]
ips = ["104.29.0.0/16", "35.217.0.0/16"]
domains = ["discord.media"]
```

`routes add mine --file rule.toml`. CLI проверяет файл до отправки (поля, подсети, порты, домены, программы
`apps`) и при ошибке выходит с кодом 2 и текстом с номером строки; приложению такой файл не уходит.
`routes remove` без `--yes` — код 2. Битый `routes.toml` правка из CLI не перезаписывает: она отказывает, пока
файл не исправлен. Включённость самой маршрутизации — `router on|off`; `settings set` её не трогает.

## Тесты

`tests run` без имён запускает все стратегии из `strategies list` в их порядке, кроме строк с `error`; с именами
— только названные, в указанном порядке. `--dpi` — набор DPI вместо стандартного. `--repeats <N>` (1–5,
по умолчанию 1) — сколько раз проверить каждую стратегию: N полных проходов по списку подряд (сначала все
стратегии один раз, потом все ещё раз), прогон длится в N раз дольше. Без `--wait` команда возвращается сразу:

```json
{
  "repeats": 1,
  "started": true,
  "strategies": 22,
  "suite": "standard"
}
```

`tests wait` и `tests run --wait` раз в 2 с спрашивают приложение о прогоне и пишут ход в stderr, по строке на
стратегию (с повторами — на стратегию в каждом проходе, `pass 2/3: 3/22 general (ALT2)`):

```
3/22 general (ALT2)
```

Когда прогон закончится, stdout получает компактный рейтинг. Порядок — как в прогоне: он уже отсортирован,
лучшая стратегия первая. `score` — счёт стратегии целиком (`ok` из `total` проверок прошли, `median_ms` —
медианная задержка и другие поля, как в `tests show --full`). С повторами `score` — сумма проходов (`total` —
проверки всех проходов, `ok` — прошедшие из них), задержки — медиана медиан проходов; ошибка запуска в любом
проходе — ошибка стратегии (`pass 2 of 3: …`). Каждый проход отдельно — в `passes` стратегии в
`tests show --full`; без повторов `passes` пуст.

`tests show <id> --failures` печатает по стратегиям сводку каждой непрошедшей проверки по всем проходам:
`{"<стратегия>": {"<цель> <вид> <статус>": {"count": N, "sample_error": "<первая строка ошибки curl>"}}}`,
например `"YouTube Tls12 Error": {"count": 3, "sample_error": "curl: (28) Connection timed out"}`. Ошибка
запуска — ключ `launch_error`; у проверки DPI `sample_error` — её код. Стратегии без сбоев не попадают в вывод.

```
{
  "canceled": false,
  "id": "2026-10-11_10-00-00",
  "ranking": [
    {
      "launch_error": null,
      "name": "general (ALT11)",
      "place": 1,
      "score": { "ok": 36, "total": 36, "median_ms": 184, … }
    },
    …
  ],
  "restore_error": null,
  "suite": "standard"
}
```

- `launch_error` не `null` — стратегия не запустилась, она в конце рейтинга. `restore_error` — после прогона
  что-то не вернулось на место, подробности в журнале. `canceled` — прогон отменён.
- Прогон завершился ошибкой (например, папка zapret не найдена) — `{"error": "…"}`, код 1.
- Прогона сейчас нет — печатается итог последнего с запуска приложения: его рейтинг или ошибка; если прогонов
  не было — `{"last": null}`.
- `--timeout <s>` ограничивает ожидание: по истечении — код 4, а прогон продолжается; ждите дальше `tests wait`.
- Во время прогона приложение не меняет zapret: `apply`, `restart` и другие команды, которые его меняют,
  отвечают ошибкой (код 1). `tests status` и `tests cancel` работают.

`tests status` печатает `{"testing": …, "live": …, "last": …}`: `live` — ход прогона, как его видит окно,
`last` — `{"run_id": "…"}` или `{"error": "…"}`.

## Рецепт: подобрать и применить лучшую стратегию

```
zapret-hub-cli start
zapret-hub-cli tests run --wait --timeout 540
zapret-hub-cli tests wait --timeout 540
zapret-hub-cli apply-best
zapret-hub-cli quick-check
```

1. `start` поднимает приложение, если оно не запущено (раздел «Если приложение не запущено»).
2. `tests run --wait` запускает стандартный набор по всем стратегиям и ждёт рейтинг. Около 15 с на стратегию:
   22 стратегии Flowseal 1.10.3 — около 6 минут. У агента с пределом времени на команду (у Claude Code — 10
   минут) `--timeout 540` оставляет запас. Код 4 — прогон ещё идёт: повторяйте `tests wait --timeout 540`, пока
   не будет 0 или 1.
3. `apply-best` ставит первую стратегию последнего завершённого стандартного прогона (не отменённого).
4. `quick-check` подтверждает, что zapret работает: `"ok": true`. Смотрите на поле, а не на код выхода: при
   `"ok": false` он тоже 0.

## Свои стратегии

```
zapret-hub-cli custom clone "general (ALT11)" mine
```

Команда печатает запись новой стратегии `general (HUB mine)`: `name`, `cloned_from`, `wf`, `blocks`. Позже ту же
запись даёт `strategies show "general (HUB mine)"`, поле `record`. Сохраните её в файл, поправьте `wf` или
`blocks` и проверьте:

```
zapret-hub-cli custom validate mine.json
zapret-hub-cli custom save mine.json
```

- `-` вместо файла читает запись из stdin.
- `--create` сохраняет запись как новую стратегию; без него меняется существующая с тем же `name`.
- Файл — UTF-8 или UTF-16LE с BOM (раздел «Файлы и stdin»).
- JSON не той формы — код 2, в приложение ничего не отправлено. Аргументы не приняты `winws --dry-run` — код 1
  с текстом ошибки.

Удалить: `zapret-hub-cli custom delete mine --yes`.

## Файлы и stdin

Команды `custom validate|save` и `zapret2 validate|save` читают файл или stdin (`-`). Допускаются UTF-8 и UTF-16LE;
BOM UTF-8 (Блокнот, `Set-Content -Encoding UTF8`) и BOM UTF-16LE (`>` и `Out-File` в Windows PowerShell 5.1) снимаются.

## Стратегии zapret2

Если в окне задана папка zapret2 («Настройки» → «Папка zapret2»; CLI её не меняет), `strategies list` после стратегий
Flowseal показывает стратегии zapret2: сначала встроенные (`zapret2:general`, `zapret2:general-sni`), потом
свои. `apply`, `strategies show` и `tests run` принимают эти имена как есть, прогон может смешивать оба движка.
Применение стратегии zapret2 ставит службу `zapret2` и удаляет службу `zapret`, применение стратегии Flowseal —
наоборот.

Папка Flowseal для zapret2 необязательна. Без неё `strategies list` показывает только стратегии zapret2, а
`apply`, `tests run`, `zapret2 validate|save|delete`, `quick-check`, `restart` и `service remove` работают с zapret2.
Команды Flowseal (его стратегии, `flowseal`, `game-filter`, `ipset`, `fake`, списки, `hosts`, `checks`) отвечают
ошибкой `the zapret folder is not set: choose it in Settings`, код 1. Стратегия zapret2 с `%LISTS%`, `%BIN%` или
`%GameFilter*%` без папки Flowseal не проходит проверку: `the strategy uses %LISTS%: choose the zapret folder in
Settings` (у встроенных это поле `error` в `strategies list`).

`zapret2 info` печатает папку, версию движка и совместимость Lua (`compat`) или ошибку (`error`).

Своя стратегия — текст аргументов `winws2` в файле: глобальная часть (`--wf-*`, `--lua-init`, `--blob`), затем
профили через `--new`. Строки, которые начинаются с `#`, — комментарии. `%LUA%`, `%FILES%`, `%LISTS%`, `%BIN%` и
`%GameFilter%`, `%GameFilterTCP%` и `%GameFilterUDP%` подставляются при проверке и установке. Текст встроенной стратегии — поле `source` в выводе
`strategies show zapret2:general`: с него удобно начать.

```
zapret-hub-cli zapret2 validate mine.txt
zapret-hub-cli zapret2 save mine mine.txt --create
zapret-hub-cli apply zapret2:mine
```

- `validate` и `save` проводят полную проверку: статическую (функции `--lua-desync`, кавычки), `winws2 --dry-run`
  и `winws2 --intercept=0`. Ошибка — код 1 с полным выводом `winws2`.
- `save` без `--create` меняет существующую стратегию. Если она активна, служба ставится заново и печатается
  итог быстрой проверки, иначе — `null`.
- Имя: 1–40 символов, латинские буквы, цифры, пробел и `-_.`, начинается с буквы или цифры; зарезервированные
  имена устройств Windows (`CON`, `NUL`, `COM1` и т. п.) отклоняются. Плохое имя — код 1 от приложения.

Удалить: `zapret-hub-cli zapret2 delete mine --yes`. Встроенные стратегии и активную удалить нельзя.

## Если приложение не запущено

Команды, которым нужно приложение, отвечают кодом 3:
``Zapret Hub is not running: start it with `zapret-hub-cli start` or run zapret-hub.exe (if it is in the tray, its CLI pipe is closed: quit it from the tray and start it again)``.

`zapret-hub-cli start` запускает задачу Планировщика «Zapret Hub». Её создаёт автозапуск приложения, и она
запускает приложение с правами администратора без запроса UAC. Потом `start` до 30 с ждёт, пока приложение
ответит, и печатает `{"app": "0.6.0"}`. Если приложение уже работает, задача не запускается: с включённым CLI
ответ приходит сразу, с выключенным — код 3 и отказ `the CLI is off: enable it in Zapret Hub → Settings`.

Если автозапуск выключен, задачи нет: `start` выходит с кодом 3 и советует запустить `zapret-hub.exe` вручную
или включить автозапуск в настройках. Запуск exe вручную требует подтверждения UAC: его делает человек.

## Ограничения

- Канал один на компьютер. Если его имя уже занято другой программой (или Zapret Hub, запущенным другим
  пользователем), приложение показывает уведомление «Канал CLI занят другой программой» и работает без CLI.
- Если канал не удалось открыть по другой причине, приложение показывает уведомление «Канал CLI не открыт», а
  если он остановился, пока приложение работало, — «Канал CLI остановлен». Оба уведомления несут текст ошибки.
  Пока канала нет, CLI отвечает, как при незапущенном приложении (код 3). `start` тут не поможет: приложение уже
  работает, задача автозапуска только откроет его окно, и через 30 с `start` выйдет с кодом 3. Выйдите из
  приложения через «Выход» в меню трея и запустите его снова.
- Канал пускает пользователя, от имени которого запущено приложение. Если в окне UAC вводили пароль другой
  учётной записи, приложение работает от неё, и CLI обычного пользователя получает отказ (код 3).
- Программа, запущенная от вашего имени, может открыть свой экземпляр канала и отвечать CLI вместо приложения:
  выполнить что-либо от имени приложения она не может, но может вернуть агенту ложный ответ.
- Итог последнего прогона (`last`) хранится в памяти приложения: после перезапуска он `null`.
- `version` печатает `"app": null` и тогда, когда приложение отказало (например, CLI выключен).

## Проверка вживую

Автотесты приложение не запускают: ему нужны права администратора. Перед выпуском пройдите список вручную.
Приложение — из повышенного терминала (`npm run tauri dev`) или готовым exe; CLI — из обычного терминала:
`cargo run -q -p cli --bin zapret-hub-cli -- <команда>` или `zapret-hub-cli.exe <команда>`. Код выхода —
`echo $?` в Git Bash или `$LASTEXITCODE` в PowerShell. Каждый пункт сверяется с журналом `data\logs`.

1. CLI выключен: `status` → код 3, `{"error": "the CLI is off: enable it in Zapret Hub → Settings"}`; в журнале
   `cli: refused: the CLI is off…`.
2. Флажок «Управление из командной строки» включён и сохранён: `status` → код 0, обзор; в журнале
   `cli: get_overview: ok`.
3. `version` → `{"app": "0.7.0", "cli": "0.7.0", "protocol": 4}`, код 0.
4. `apply "general (ALT2)"` → код 0; окно и иконка трея сами показывают новую стратегию.
5. `service remove` → код 2, служба на месте. `service remove --yes` → код 0, `sc query zapret` службу не
   находит. `apply "general (ALT2)"` возвращает её.
6. `tests run --wait general "general (ALT2)"` → ход в stderr, рейтинг из двух строк, код 0.
7. `tests run --wait --timeout 5` → код 4, прогон идёт дальше. Пока он идёт: `apply general` → код 1 с ошибкой
   про прогон; `tests status` отвечает сразу. Затем `tests wait` → рейтинг, код 0.
8. `custom clone general mine` → запись; `general (HUB mine)` есть в `strategies list`. Запись в файл →
   `custom validate` → код 0; файл `{"name": 1}` → код 2; `custom delete mine --yes` → код 0.
9. Вкладка «Настройки» открыта. `settings set theme dark` → окно сразу тёмное, в списке темы на вкладке
   «тёмная». Введите на вкладке адрес прокси и не сохраняйте; `settings set socks5 127.0.0.1:2080` → код 0,
   поле остаётся с вашим адресом, а «Сохранить» записывает его поверх адреса агента (`settings get`).
   `settings set cli_enabled false` → код 0; флажок на вкладке снят сразу, без перехода на другую вкладку;
   `status` и `start` → код 3, `the CLI is off…`. Включите флажок на вкладке снова и сохраните:
   `status` → код 0.
10. Выход из приложения через трей: `status` → код 3, `Zapret Hub is not running…`. С включённым автозапуском
    `start` → `{"app": "0.6.0"}` не позже чем через 30 с, приложение в трее; с выключенным — код 3 и совет.
11. Занятое имя: выйти из приложения, в обычном PowerShell выполнить
    `$p = [System.IO.Pipes.NamedPipeServerStream]::new('zapret-hub-cli')`, запустить приложение → уведомление
    «Канал CLI занят другой программой», в журнале `cli: \\.\pipe\zapret-hub-cli is not open: …`. Затем
    `$p.Dispose()`, перезапуск приложения → `status` снова отвечает.
12. zapret2, с распакованным релизом zapret2: `settings set zapret2_dir <папка релиза>` → код 2, настройки не
    меняются; в окне «Настройки» → «Папка zapret2» выбрать папку релиза и сохранить; `settings get` →
    `zapret2_dir` с ней; `zapret2 info` →
    версия и `compat`. Текст `strategies show zapret2:general` (поле `source`) в файл → `zapret2 validate` →
    код 0; `zapret2 save mine <файл> --create` → `{"ok": true}`; `apply zapret2:mine` → `sc query zapret2` — RUNNING,
    `sc query zapret` службу не находит; `apply general` → наоборот. `zapret2 delete mine` → код 2, с `--yes` →
    код 0.
13. NekoBox с mixed inbound запущен, скрипт `discord-udp-proxy.ps1` закрыт. «Маршруты» → «Добавить из профиля» →
    «Discord голос», переключатель «Маршрутизация» → в шапке «прокси отвечает», голосовой канал Discord соединяется,
    в «Потоках» строки «прокси» с растущими ↑/↓; в журнале NekoBox — UDP к `104.29.*`/`35.217.*`.
14. Приоритет: служба zapret запущена со стратегией; `winws.exe --debug=1` той же стратегии вручную (служба
    остановлена) при включённой маршрутизации не печатает пакетов к подсетям правила (спецификация, раздел 11, риск «Приоритет winws»).
15. Закрыть NekoBox посреди звонка: не позже чем через 20 с (две проверки) в шапке «прокси недоступен, трафик идёт
    напрямую», на значке трея красная точка; новый звонок идёт напрямую (если zapret это пропускает); запустить
    NekoBox — не позже чем через 10 с новые потоки и потоки звонка снова «прокси».
16. «Тесты» → прогон двух стратегий: в шапке «пауза: идёт тест», после прогона — «включена».
17. `apply zapret2:general` (и обратно `apply general`) при включённой маршрутизации: служба другого движка
    стартует, маршрутизация снова «включена» (DLL нового движка), звонок работает.
18. CLI: `router status` → JSON; `routes add mine --file rule.toml` с `apps = ["Discord"]` → код 2 и
    `is not a program`; `routes remove mine` → код 2, с `--yes` → код 0; `router off` → вкладка
    показывает «выключена», `zapret-hub.toml` — `router_enabled = false`.

    сквозного теста ещё `$env:ROUTER_SOCKS5 = '127.0.0.1:2080'` (работающий прокси);
    `cargo test -p router --test live -- --ignored` → все тесты проходят (`WINDIVERT_DLL` нужен всем, `ROUTER_SOCKS5` —
    сквозным).
20. Пункт трея «Маршрутизация: вкл/выкл» переключает её так же, как переключатель вкладки; вкладка и значок сразу
    показывают новое состояние.
21. Смена движка в обход хаба: при включённой маршрутизации остановить службу одного движка и запустить другой
    вручную (`service.bat` Flowseal или служба `zapret2`). DLL выбирается только при синхронизации (запуск хаба,
    сохранение настроек, конец паузы; спецификация, раздел 11): без перезапуска хаба звонок по-прежнему идёт через
    прокси (если нет — записать, с какой парой движков); после перезапуска хаба маршрутизация «включена».
22. NekoBox запущен, «Добавить из профиля» → «Discord целиком», включить маршрутизацию: Discord (приложение,
    перезапущенное после включения, и discord.com в браузере без «безопасного DNS») загружается; в «Потоках» строки

    снова «прокси», пометки «напрямую» сняты.
